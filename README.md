# Compiler / Compiladores

This repository contains the development of a compiler as part of the Compilers course.

Este repositorio contiene el desarrollo de un compilador como parte del curso de Compiladores.

## Build Instructions / Instrucciones de Armado

Follow these steps to compile the project using CMake:
Sigue estos pasos para compilar el proyecto usando CMake:

1. **Configure the project / Configurar el proyecto:**
   ```bash
   cmake -S . -B build
   ```

This creates the build directory and generates the build system.
Esto crea el directorio build y genera el sistema de construcción.

2. **Compile / Compilar:**
    ```bash
    cmake --build build
    ```

This compiles the source code and creates the executable.
Esto compila el código fuente y crea el ejecutable.

3. **Run / Ejecutar:**
    ```bash
    ./build/compiler
    ```

## Project Structure / Estructura del Proyecto

The project is built using **CMake** and follows a modular C structure:
El proyecto está construido utilizando **CMake** y sigue una estructura modular en C:

* `src/`: Core logic (Lexer, Parser, etc.). / Lógica central (Léxico, Sintáctico, etc.).
* `include/`: Header files. / Archivos de cabecera.
* `tests/`: Test suites and source code samples for compilation. / Pruebas y muestras de código para compilar.
* `docs/`: Documentation and design notes. / Documentación y notas de diseño.
* `build/`: Directory for build artifacts (generated by CMake). / Directorio para artefactos de construcción (generado por CMake). 
* `CMakeLists.txt`: Build configuration. / Configuración de construcción.

### Development Note / Nota de Desarrollo

For the current phase of the course, the established compiler architecture format will not be strictly enforced while developing the analysis-related practices (such as regex processing, NFA construction, and intermediate components).

Every single individual feature will have their own branch with their own respective README.md file with instructions on how to use it. Once all compiler phases are completed, legacy individual practices will be stored in a separate directory for reference, and the entire project will be refactored and adapted to fully comply with the established compiler architecture format.

En la fase actual del curso, no se seguirá estrictamente el formato arquitectónico definitivo del compilador mientras se desarrollan las prácticas relacionadas con el análisis (como procesamiento de regex, construcción de NFA y componentes intermedios).

Cada funcionalidad individual tendrá su propia rama con su respectivo README.md con instrucciones de uso. Una vez que todas las fases del compilador estén completas, las prácticas individuales anteriores se almacenarán en un directorio separado para referencia, y todo el proyecto se refactorizará y adaptará para cumplir completamente con el formato arquitectónico establecido del compilador.

## Branching Strategy / Estrategia de Ramas

To maintain code integrity and professional workflow, the following strategy will be followed:
Para mantener la integridad del código y un flujo de trabajo profesional, se seguirá la siguiente estrategia:

* **Main Branch**: Represents the "production" or stable state. No direct commits are allowed (except for the initial setup).
    **Rama Main**: Representa el estado estable o de "producción". No se permiten commits directos (excepto la configuración inicial).
* **Feature Branches (`feature/name`)**: Used for developing new compiler phases or components.
    **Ramas de Funcionalidad (`feature/nombre`)**: Utilizadas para desarrollar nuevas fases o componentes del compilador.
* **Fix Branches (`fix/name`)**: Used for bug fixes and patches.
    **Ramas de Corrección (`fix/nombre`)**: Utilizadas para correcciones de errores y parches.

*All features must be merged into main via Pull Request/Merge Request.*
*Todas las funcionalidades deben integrarse a main mediante Pull Request/Merge Request.*
